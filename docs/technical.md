# 手机刷机工具如何工作

[返回首页](../README.md) · [刷机教程](GUIDE.zh-CN.md) · [软件来源](SOURCES.zh-CN.md)

本文解释本仓库工具的主要工作方式，供需要进一步核对的人参考。想直接刷机，请按中文教程操作，不需要根据内部存储名称手工拼刷写命令。

## 整个过程

1. 检查手机环境，下载并核对所选版本的文件。
2. 取得原厂系统的管理员连接，核对路由器型号、闪存芯片和存储位置。
3. 备份设备数据，向空闲位置写入临时安装系统，再读回核对。
4. 重启路由器，手机连接临时 Wi-Fi，重新查找并检查设备。
5. 从临时系统把正式固件写进路由器。
6. 手机连接正式 Wi-Fi，核对型号、原设备数据和系统类型，确认正式安装成功。

代码仅启用已配置的 `rd03v2` 设备类型。相似型号、相同名称或存在相同漏洞，都不足以证明能使用同一套闪存布局和固件。

## 主要程序

| 文件 | 作用 |
| --- | --- |
| `install.py` | 组织安装步骤，调用检查、备份、写入和最终核对 |
| `devices.py` | 保存支持的设备、固件来源和有关参数 |
| `release.py` | 获取发布信息、下载文件、核对大小与校验值 |
| `ish_preflight.py` | 在手机上进行只读连接和进度保存检查 |
| `ish_backend.py` | 把安装过程接入 iSH 网络操作 |
| `ish_network.py` | 处理手机网络地址、接口编号和设备身份检查 |
| `chain.py` / `channel.py` | 原厂系统连接与安装所用通道 |
| `revert.py` / `restore.py` | 恢复原厂的相关工具；本仓库尚未完成 iSH 实机恢复验证 |

## 为什么要检查多个地址？

手机会先后连接原厂、临时和正式 Wi-Fi，每个网络里的路由器地址或手机接口编号可能不同。工具在继续操作前，会比较设备信息、检查当前连接和原设备的 ART 硬件数据，不能只凭一个看起来相似的 IPv6 地址就发送密码或刷写命令。

ART offset 6 生成的地址只是候选，使用前仍要验证。源码和具体版本见[来源说明](SOURCES.zh-CN.md)。

## 进度文件怎么避免重复刷写？

`resume.json` 保存这次安装用的设备类型、版本、镜像信息、网络后端、连接参数和已完成阶段。它以私有文件权限保存，更新时使用原子替换，减少进度写到一半留下坏文件的情况。

继续安装时，工具会核对选定文件和原记录是否一致。写入已经启动后，iSH 的默认继续操作会改为检查结果，而不是再次写入。阶段名称和用途见 [iPhone 使用说明](../README-ISH.zh-CN.md)。

这个机制不能代替持续供电，也不能保证任何断电或系统中断都能自行恢复。结果不确定时，先用原记录检查，不能新开一个任务重刷。

## 安装检查为什么不能省略？

- **型号检查**：避免把相似外观设备当成同一硬件。
- **闪存支持检查**：确认该固件声明支持实际探测到的芯片。
- **存储位置检查**：避免写到正在使用或错误的系统区域。
- **文件完整性检查**：核对 SHA-256，以及对应 UBI / ITB 文件是否配套。
- **写入后读回**：不能只凭写入命令返回成功判断内容正确。
- **系统类型检查**：`tmpfs` 表示本次的临时系统；最终还要确认 `overlay`、型号、设备数据及要求的分区大小。

这些检查共同构成安装流程；单独 ping 通、看到 SSH 响应或网页能登录都不能替代全部检查。

## 下载与手机环境

下载器按每段 2 MiB 请求文件，检查响应中的范围和总长度；网络错误时保留 `.part` 文件，在完整下载并通过可信摘要检查后才转为正式缓存。服务器不支持分段请求时会重新下载，不把整个文件接到旧片段后面。

iSH 使用的网络接口与普通 Linux 电脑不同，本仓库通过 socket 进行必要网络操作，而不是直接依赖 Linux 的 Netlink 或网络 sysfs。旧版 OpenSSH 8.6 使用默认 SCP；较新版本通过 `-O` 保持兼容的文件传输方式。
